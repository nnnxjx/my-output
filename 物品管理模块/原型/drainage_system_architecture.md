# 城市排水管理系统架构设计

## 1. 系统概述
本城市排水管理系统旨在提供一个基于Web的平台，实现对城市排水设施的实时监控、管理和数据分析，通过SCADA系统集成实现自动化监控和预警功能。

## 2. 系统架构

### 2.1 总体架构
```
+----------------+     +------------------+     +------------------+
|                |     |                  |     |                  |
|  前端Web界面   |<--->|  后端API服务     |<--->|  SCADA系统       |
|                |     |                  |     |                  |
+----------------+     +--------+---------+     +------------------+
                               ^
                               |
                        +------+------+
                        |             |
                        |  数据库系统  |
                        |             |
                        +-------------+
```

### 2.2 技术栈选择

#### 2.2.1 前端技术栈
- **框架**: React.js
- **状态管理**: Redux
- **UI组件库**: Ant Design
- **图表库**: ECharts
- **地图可视化**: Mapbox
- **路由**: React Router
- **HTTP客户端**: Axios

#### 2.2.2 后端技术栈
- **框架**: Python Flask
- **ORM**: SQLAlchemy
- **认证**: JWT (JSON Web Token)
- **API文档**: Swagger/Flask-RESTPlus
- **WebSocket**: Flask-SocketIO (实时数据推送)

#### 2.2.3 数据库
- **主数据库**: MySQL
- **缓存**: Redis (用于实时数据缓存)

#### 2.2.4 SCADA集成
- **协议支持**: Modbus TCP/IP, OPC UA
- **数据采集服务**: 独立Python服务
- **消息队列**: RabbitMQ (用于SCADA数据传输)

## 4. 数据库设计

### 4.1 用户表(users)
- id: 主键
- username: 用户名
- password_hash: 密码哈希
- email: 邮箱
- role: 角色 (admin, operator, viewer)
- status: 状态
- created_at: 创建时间
- updated_at: 更新时间

### 4.2 排水设施表(facilities)
- id: 主键
- name: 设施名称
- type: 设施类型 (泵站, 阀门, 管网, 检查井等)
- location: 位置信息
- coordinates: 坐标信息
- status: 运行状态
- description: 描述
- created_at: 创建时间
- updated_at: 更新时间

### 4.3 监控数据表(monitoring_data)
- id: 主键
- facility_id: 设施ID (外键)
- parameter_name: 参数名称 (水位, 流量, 压力等)
- parameter_value: 参数值
- unit: 单位
- timestamp: 时间戳
- is_alarm: 是否告警

### 4.4 告警规则表(alarm_rules)
- id: 主键
- facility_id: 设施ID (外键)
- parameter_name: 参数名称
- condition_type: 条件类型 (大于, 小于, 等于等)
- threshold_value: 阈值
- alarm_level: 告警级别
- description: 描述

### 4.5 告警记录表(alarm_records)
- id: 主键
- facility_id: 设施ID (外键)
- alarm_rule_id: 告警规则ID (外键)
- trigger_value: 触发值
- status: 状态 (未处理, 处理中, 已处理)
- created_at: 创建时间
- handled_at: 处理时间
- handled_by: 处理人

## 5. SCADA集成设计

### 5.1 数据采集流程
1. SCADA系统采集现场设备数据
2. 数据采集服务通过Modbus/OPC UA协议连接SCADA系统
3. 数据采集服务将数据转换为标准格式并发送到消息队列
4. 后端API服务从消息队列接收数据并存储到数据库

### 5.2 实时数据推送
1. 后端API服务通过WebSocket向前端推送实时数据
2. 前端接收数据并更新界面展示

### 5.3 控制命令下发
1. 前端发送控制命令到后端API
2. 后端API验证权限并转发到SCADA系统
3. SCADA系统执行控制命令到现场设备
